# 复习调度算法重设计 — 外部模型提示词（2026-09-28）

> 用途：把下面的提示词复制给能力较强的通用模型，收集调度策略设计方案；
> 拿到方案后走 SPEC §7 修订 → scheduler.rs 重写（TDD）→ 设置页/弹窗同步。

```
我开发了一款 Windows 常驻托盘的闪卡复习工具「闪记 FlashMemo」（Tauri 2 + Rust + SQLite，纯本地、无网络），
想请你帮我设计一套新的复习调度算法。以下是完整背景：

【产品定位与使用方式】（和 Anki 不是同一赛道，请不要默认按 Anki 的思路设计）
- 用户画像：准备跳槽面试的开发者，卡片内容全是"八股文"知识点（MySQL / Redis / JVM / JUC 等），
  每张卡就是一道面试口述题（例："事务的隔离级别有哪些？"）
- 使用方式：软件常驻后台工作，用户设置一个弹窗间隔（如每 5 分钟），到点后弹出一个小窗，
  一次展示 N 张卡（如 3 张）。每张卡流程：看问题 → 脑子里过一遍 → 点"显示答案"对照 → 自我评估 → 切下一张
- 核心目标：让高频知识点保持"长期可讲述"（面试时能当场讲出来），而不是考试式的精确回忆；
  同时以低打扰的方式融入工作节奏
- 典型使用节奏是"间断式"：白天被弹窗打断 30~60 次，每次几秒钟，而不是坐下来连续突击

【当前实现与痛点】
现在用的是 FSRS-6（Rust 的 fsrs-rs crate），四档评分：重来 / 困难 / 良好 / 简单。问题：
1. 四档自评太细：口述复习的场景下用户分不清"困难"和"良好"的边界，评分噪声大
2. FSRS 的分钟级学习步骤（1m/5m/10m）是"连续突击"模式，与间断打扰的节奏冲突（已做开关可关闭）
3. 我们的场景更适合三档自评：不了解 / 熟悉 / 可以讲出来
4. FSRS 的威力依赖大量复习历史做参数优化，个人工具的用户不会去跑优化器，用默认参数时它就是一个复杂黑盒
5. FSRS 输出分数天的精确间隔，但我们的应用粒度是分钟/小时/天，很多精度是浪费的

【我想请你设计的】
一套简单、可解释、可调的调度规则：
- 输入：卡片最近的评分序列 / 当前间隔 / 复习次数（数据模型可以改，不必兼容 FSRS）
- 评分：不了解 / 熟悉 / 可以讲出来（三档，可以给不同权重）
- 输出：这张卡的下次出现间隔（分钟/小时/天的量级即可，不需要小数天）
要求：
a) 规则要简单到能向用户一句话解释（"你评了熟悉，所以 3 天后再见"）
b) 关键参数可调：最短间隔、最长间隔、熟练度增长倍率之类
c) 边界安全："不了解"不能造成 1 分钟无限循环（要有下限约束）；同一张卡一天最多出现 1~2 次
d) 有"毕业感"：评"可以讲出来"的卡片间隔快速增长；连续"不了解"的卡快速回落并提示用户重点对待
e) 可选：是否要为每个卡包/每张卡维护一个"熟练度"标量（类似 SM-2 的 ease factor 或 Leitner 盒子的层级）
f) 告诉我如何处理已有数据：从 FSRS 的 stability/difficulty 状态迁移（映射 or 降级重置）

【请输出】
1. 完整的规则设计：评分 → 间隔的规则表或公式（含具体数值），设计理由
2. 伪代码（含边界情况：新卡、连续不了解、间隔达到上限后如何处理）
3. 建议的可调参数清单 + 默认值
4. 与"每次弹窗 N 张卡 + 固定弹窗间隔"的交互注意事项（例如：到期卡多于一次会话容量时，优先弹哪张）
5. 简短对比：直接用 FSRS 但把四档映射为三档（如 不了解=Again、熟悉=Hard/Good、可以讲出来=Easy），
   和完全自研简单算法相比，各自的优劣和你的推荐

【参考方向（不限于，欢迎更好的）】
- 简化版 SM-2（只保留 ease factor）
- Leitner 盒子（固定间隔阶梯：如 1d / 3d / 7d / 21d / 60d，评分决定升/降/留在哪一级）
- 倍率法：三档各对应一个间隔倍率（如 不了解 → 重置到下限附近，熟悉 → ×1.5，可以讲出来 → ×2.5），
  外加最短/最长间隔钳制
- FSRS 降维映射

【实现约束】
Rust 实现、纯本地、不做 ML 训练（固定参数公式即可）；个人使用规模：几千张卡。
```
