# 闪记 FlashMemo — M1 MVP 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 SPEC §18 M1 核心闭环：导入 Markdown 笔记 → 定时弹窗复习 → 评分 → FSRS 调度，托盘常驻。

**Architecture:** Tauri 2 双窗口（主窗口管理 + 无边框复习弹窗），前端 React 仅做展示与交互，全部业务在 Rust：`parser.rs`（纯函数解析）、`scheduler.rs`（学习步骤 + fsrs-rs 调度）、`db.rs`（rusqlite）、`engine.rs`（15s tick，弹/不弹是纯函数决策）。Rust command 层是薄壳。

**Tech Stack:** Tauri 2 (tray-icon) / React 18 + TS strict + Vite / rusqlite(bundled) / fsrs / chrono / markdown-it + markdown-it-mark / Vitest。

**Spec:** [SPEC.md](../../SPEC.md)（本计划从 SPEC 论证；执行者两个文件都要读。M1 范围 = SPEC §18 的 M1 行，F13/F14/F15/F16/F17 等 P1/P2 功能一律不做。）

## Global Constraints（所有任务隐含遵守）

- 平台：Win10 1809+ / Win11 x64；数据目录 `%APPDATA%\FlashMemo\`（开发期可在 `%APPDATA%` 下直接建）。
- 安装包 ≤ 8 MB、空闲内存 ≤ 60 MB（M3 验收口径，M1 不测但不得引入大依赖）。
- 弹窗：约 440×380、无边框、置顶、默认不抢焦点；随机位置距屏幕边缘 ≥ 20px，与上次弹出位置偏移 ≥ 100px。
- 引擎 tick = 15 秒；定时到点 → 窗口可见 < 300ms。
- 调度默认值：学习步骤 1m/5m/10m；目标保留率 0.90；跳过重入队 30 分钟；弹窗间隔 10 分钟；每次张数 1；学习时段 09:00–22:30。
- 每次评分立即写库（含 review_log），不允许内存攒批。
- 核心功能（导入/调度/复习/存储）零网络请求；UI 文案全部中文；注释与标识符英文。
- git 仅本地初始化（用户后续自行挂远程），Conventional Commits、中文描述。
- fsrs crate 的 `next_states(Option<MemoryState>, f32 retention, f32 elapsed_days)` 返回四个分支（`again/hard/good/easy`），各含 `memory_state` 与 `interval`（**分数天**）；若 crate 小版本签名有出入，以行为契约（本计划各测试断言）为准适配。

## Review Focus（规格未明说、最可能咬人的五类输入）

1. **围栏代码块内的 `#`/`###` 行**（SQL 注释等）不得被当作标题拆卡 → Task 2 `parses_code_fence_hash_as_content`。
2. **CRLF 换行与 UTF-8 BOM** 的笔记文件必须正常解析 → Task 2 `parses_crlf_and_bom`。
3. **重复导入不得清空复习进度**（due/记忆状态/评分次数原样保留）→ Task 4 `reimport_preserves_progress`。
4. **学习时段外、暂停中、已有弹窗时绝不弹第二窗** → Task 8 `popup_decision_suppressed`。
5. **评分后立刻崩溃不得丢评分**（评分与其日志同一事务落盘）→ Task 6 `rate_persists_review_log`。

### Task 5: 调度器 `scheduler.rs`（TDD，本计划的核心）

**Files:**
- Create: `src-tauri/src/scheduler.rs`；Modify: `src-tauri/src/lib.rs`

**Interfaces:**
- Consumes: `fsrs::{FSRS, MemoryState}`。
- Produces:
```rust
pub enum Rating { Again, Hard, Good, Easy }
pub enum CardState { New, Learning, Review, Relearning }
pub struct ScheduleConfig { pub steps_min: Vec<u32>, pub retention: f32, pub skip_delay_min: u32 } // 默认 [1,5,10] / 0.90 / 30
pub struct CardSched { pub state: CardState, pub stability: Option<f32>, pub difficulty: Option<f32>,
                       pub learning_step: usize, pub last_review_at: Option<DateTime<Utc>> }
pub struct ScheduleOutcome { pub state: CardState, pub stability: Option<f32>, pub difficulty: Option<f32>,
                             pub learning_step: usize, pub due_at: DateTime<Utc> }
pub fn review(card: &CardSched, rating: Rating, now: DateTime<Utc>, cfg: &ScheduleConfig) -> Result<ScheduleOutcome>
pub fn skip(card: &CardSched, now: DateTime<Utc>, cfg: &ScheduleConfig) -> DateTime<Utc>       // 不评分语义
pub fn preview(card: &CardSched, now: DateTime<Utc>, cfg: &ScheduleConfig) -> Result<[Option<f64>; 4]> // 各评分的下次间隔（分钟）
```
- 语义（SPEC §7 逐条）：学习/重学阶段走 `steps_min`（Again→第 0 步；Hard→停留当前步、**新卡首评 Hard 视为进入第 1 步**（0 起）；Good→推进一步、最后一步 Good 毕业；Easy→立即毕业）；毕业与复习阶段走 fsrs：`elapsed_days = (now - last_review_at)` 分数天，`next_states` 后按评分取 `interval`（分数天 → 分钟数 ×1440）；Review 阶段 Again → Relearning 第 0 步（重学毕业时用当次评分结果调 fsrs 取间隔）。

  - `review_again_enters_relearning`、`relearning_good_graduates_back_to_review`（due < now+30min 且 > now）；
