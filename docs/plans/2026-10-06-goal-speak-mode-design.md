# 「讲出型今日目标 + 节奏算法」设计记录（2026-10-06）

> 来源：外部评审意见（用户带去评审并带回），本文件是**实现依据**与**对评审的偏差说明**。
> 需求与最终口径同步在 [SPEC.md](../../SPEC.md) §7.9；纯函数实现见 `src-tauri/src/goal.rs`。

---

## 1. 评审的核心判断

1. **"今天掌握 N 张"按字面意思不做。** 本应用"掌握"= 连续 3 次「可以讲出来」且跨 3 个不同学习日，
   当天做不到，做出来要么名不副实、要么变成债，与产品哲学冲突。
2. **改做"今天讲出来 N 张"**：当天能做到的最小一步掌握，本身是一次成功的主动回忆；界面上不用"掌握"这个词。
   真正的"掌握数"作为**附带成绩**展示，不当目标。
3. **节奏算法不追产出缺口。** 设目标时把"讲出 N 张"按历史讲出率换算成一个**固定的复习份额**，
   之后节奏只按这份额走。最坏情况等于一个复习型目标，结构上不会出现轰炸。
4. **加压只能来自用户事先同意的投入，不能来自产出缺口。**

## 2. 采用的算法（已实现于 `goal.rs`）

```
p            = clamp( (近14学习日有效讲出 + 2) / (展示 + 5), 0.25, 0.9 )   // 先验平滑
分母"展示"    = 排除该卡当天已讲出之后的评分（否则高估复习需求）
budget       = clamp( ceil(N / p), N, 4N )                              // 设目标时冻结
still_need   = ceil( (N − 已讲出) / p )                                  // 讲出越多只会变松
remaining    = min( still_need, budget − 时段内已复习 )                    // 份额封顶
interval     = clamp( (时段结束 − 现在) / ceil(remaining / 每轮张数),
                      max(3, 计划间隔 × 0.5), 60 )
```

**评审要求的三条性质，均已写成单测**（`goal.rs::tests` + `engine.rs` 的集成测试）：

- 产出一直为 0 时，弹窗轮数被份额封顶，且份额用完即回落常规节奏；
- 间隔永不低于计划间隔的 0.5 倍（复习型同样适用）；
- 已完成数增加时间隔不会变短。

## 3. 实现中对评审的两处偏差（重要）

### 3.1 讲出计数改成从 `review_log` 事件出发，而不是读 `card.speak_days`

- 评审 §5.3 要求：**之后评了「不了解」不回退**——"记的是'讲出来过'这件事"。
- 但调度器在任何非「可以讲出来」评分时会把 `speak_days` 清空（掌握连击回到起点，这是既有且正确的行为）。
  若计数直接读 `speak_days`，进度条会在用户眼皮底下**倒退**，与评审要求冲突。
- 因此：`speak_cards_on_day` = `COUNT(DISTINCT card_id) WHERE rating = 3 AND 学习日 = 今天`，
  即"今天讲过这张卡"这一**事件**，天然按卡去重、天然不回退。
- 连带影响：`pushable_pool_left`（可推进卡池）也用同一事件判定，避免同一张卡一天被重复计入可推进。

### 3.2 `masteredToday`（达成掌握数）保留按卡的当前状态算

- 它是**附带成绩**而非目标，所以用快照：`speak_days` 含今天且不同学习日数 ≥ 阈值。
- 已知取舍：该卡当天之后若被评「熟悉」，连击**真的**被打破了，这个数字会跟着下降——
  这是诚实的（掌握确实回退了），且它不参与任何排程决策。已在 SPEC §7.9 注明。
- 它**不含链式门槛**（邻居是否达标），即被邻居拖住的卡也算"已掌握"。

## 4. 一并修掉的两个既有问题（评审 §3 附带指出）

1. **复习型目标在时段末尾也会压到 3 分钟地板** → 现在两种模式都用 `max(3, 计划间隔 × 0.5)` 托底。
2. **连续逃避惩罚会与目标节奏叠加**（越逃避弹越密）→ 有目标节奏时惩罚只把张数减到 1，不再压缩间隔。

## 5. 本轮未做（评审建议中的可分离部分，留待后续）

- **仪表盘的长期掌握展示**（评审 §7：本周新掌握 X 张、卡包掌握率曲线）——评审自身也把它列为
  与"今日目标"分离的另一半需求。本轮只做了目标侧。
- **组队层面的两处微调**：今天已讲出的卡往后排；被关联卡拖住的卡优先排进复习。
  （既有调度已通过 `gap_speakable` 与 2 小时时间下限把刚讲过的卡推远，所以不是必需项。）
- **「已掌握 · 等待关联卡」徽标**。
- **目标类型命名的最终拍板**：本轮采用评审推荐词「讲出张数」；改词只影响一处 UI 文案与
  `goal_mode` 的取值字符串。

## 6. 防刷漏洞的处理（对照评审 §6）

| 漏洞 | 处理 |
|---|---|
| 同一张卡反复评 | 按卡去重（事件计数） |
| 提前评 / 组卷挑熟卡 | 计数以"今天是否真的产生了 `rating=3` 评分"为准，规则只有一份 |
| 引擎为凑数挑容易的卡 | **没有**按"讲出概率"挑卡，组队逻辑一行未改（避免算法替用户回避难卡） |
| 跳过难卡 | 跳过的卡原样回队，不专门处理 |
| 新建简单卡刷数 | 受 §7.4 每日新卡配额限制 |
| 不诚实乱按「讲出来」 | 目标层不做监控；防线是跨 3 天归档 + 归档抽查 |
