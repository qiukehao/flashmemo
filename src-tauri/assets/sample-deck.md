## MySQL

### 事务的隔离级别有哪些？

> [!note] 傻瓜讲解
> 把隔离级别想象成四个档位的隐私保护罩：读未提交＝不穿衣服，读已提交＝穿外套，可重复读＝防窥服，串行化＝排队。

> [!note] ✏️ 面试回答
> 1. 读未提交（脏读）
> 2. 读已提交（不可重复读）
> 3. 可重复读（MySQL 默认，间隙锁防幻读）
> 4. 串行化

### B+ 树和 B 树的区别？

- B 树每个节点都存数据，B+ 树只有叶子节点存
- B+ 树叶子之间有双向链表，范围查询更快
- 非叶子节点只存索引，单页能放更多键 → 树更矮 → 磁盘 IO 更少

### InnoDB 有哪些锁？

| 锁 | 粒度 | 典型场景 |
| --- | --- | --- |
| 行锁 | 行 | UPDATE 命中索引 |
| 间隙锁 | 区间 | 可重复读下防幻读 |
| 表锁 | 表 | DDL / 锁全表扫描 |
| 意向锁 | 表级标记 | 快速判断表里有没有行锁 |

### 什么是回表？

普通索引的叶子节点存的是主键 ID，查到主键后还要再去聚簇索引里取整行——这一趟就是回表。覆盖索引（查询列都在索引里）可以避免它。

## Redis

### 缓存穿透、击穿、雪崩的区别与对策？

> [!note] 傻瓜讲解
> 穿透＝查**根本不存在**的数据（缓存永远不会有）→ 布隆过滤器挡掉；击穿＝**一个热点** key 过期瞬间打穿到库 → 互斥锁重建；雪崩＝**一大片** key 同时过期 → 过期时间加随机抖动。

### Redis 为什么快？

1. 纯内存操作
2. 单线程无锁竞争（6.0 前网络 IO 也单线程）
3. IO 多路复用（epoll）
4. 高效数据结构（SDS / 跳表 / 压缩列表）

### 持久化 RDB 和 AOF 怎么选？

- RDB：定时快照，文件小恢复快，可能丢最后几分钟数据
- AOF：追加写命令，最多丢 1 秒，文件大恢复慢
- 生产常用：混合持久化（4.0+）

## 网络

### 从输入 URL 到页面展示，发生了什么？

> [!question]
> 用你自己的话，按 DNS → TCP → TLS → HTTP → 渲染的主线讲一遍，重点说清每一步的协议与失败表现。

DNS 解析 → TCP 三次握手 → TLS 握手 → 发 HTTP 请求 → 服务端处理返回 → 浏览器解析渲染（HTML/CSS/JS）。面试加分点：提到缓存层级、连接复用与 CDN。

### TCP 三次握手为什么是三次？

两次无法确认「我能收到你」的反向通道；三次让双方都确认了收发能力，同时同步初始序列号。
